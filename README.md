# dsh-deepseek-billing

> DeepSeek 峰谷计费插件（梁文峰 / 梁文谷）：实时判断当前处于官方高峰时段还是闲时段，按官方价表计算当前会话窗口（含子代理）的 token 消耗与费用，并把这个面板挂到 ui-beautify 的插件面板里。

## 它做什么

**峰谷判定**：面板顶部的状态卡会显示当前时段——红色「梁文峰 · 高峰」或绿色「梁文谷 · 闲时」，并给出距离下一次换档的秒级倒计时，周末（周六与周日）全天按闲时处理。状态卡右侧的 ↻ 按钮可以随时手动刷新。

**费用统计**：插件按官方价表逐事件计价，覆盖输入未命中、缓存命中与输出（含推理）三类 token，默认以人民币显示、也可以切成美元（汇率在线刷新，也支持手动填写，默认 7.16）。统计范围是当前会话加上它派生出的子代理会话树——已经结束的子代理也会通过持久化日志计入，因此窗口总额是完整的。

**价格维护**：官方调价时不必改代码，在面板的「价格配置」里直接改即可——每个模型族四个独立输入框（高峰输入 / 高峰输出 / 闲时输入 / 闲时输出），留空即用内置价；覆盖值存在浏览器本地，改回来用「清空手动值」。页脚会如实显示当前用的是「内置官方 <日期>」还是「已手动覆盖」。模型匹配按**族前缀**进行，所以 DSH 换新模型名（加日期后缀、新变体）时会自动继承该族价格；万一是完全没见过的族，页脚会**点名**提示去补价，而不是悄悄算 0。

**窄宽度自适应**：右侧面板被挤压时，卡片与文本会先隐藏溢出内容并显示省略号，再用容器查询逐级遮挡次要信息——宽度不足 320px 时收紧内边距、换档提示降到 11px 但始终保留；不足 250px 时隐藏脚注并缩小金额；不足 190px 时隐藏倒计时并让表单换行。

**降级可用**：ui-beautify 是可选的——装了就通过「🧩 插件面板」使用（面板随插件面板的标签页切换），没装的话会话标题栏会出现一个「💰 计费」按钮，点开是一张可拖动、可缩放的浮动卡片，内容与插件面板里完全一致；两者不会同时出现，装上或卸载 ui-beautify 时入口会自动切换，之前开着的面板也会跟着回来。本插件不占用会话头部的其它位置。

## 安装

```bash
# 开发态（本地源码目录）
dsh plugin --profile web add file:D:/DeepseekPlugin/dsh-deepseek-billing

# 发布态（推荐：钉死提交，避免 install 时回退到旧版本）
dsh plugin --profile web add github:Zalpha263/dsh-deepseek-billing#<完整40位commit>
```

装完**重启 DSH**（Host 半区需要加载），然后在「🧩 插件面板」里选择「💰 峰谷计费」标签打开即可；如果没有安装 ui-beautify，改用会话标题栏的「💰 计费」按钮打开独立浮动卡片。注意 `file:` 安装得到的是**副本**，每次改完源码都要重新执行上面的 add / install 命令同步，之后 Client 改动硬刷新（Ctrl+F5）、Host 改动重启 DSH。

## 面板说明

| 组件 | 控件 | 作用 |
|------|------|------|
| 状态卡 | 徽章 | 当前时段，高峰红、闲时绿 |
| 状态卡 | 倒计时 | 距离下一次换档的 HH:MM:SS |
| 费用卡 | 总额 | 当前窗口的费用，可在人民币与美元之间切换 |
| 明细卡 | Token 表 | 缓存命中 / 未命中 / 输出（含推理）/ 推理 / 总消耗 |
| 价格配置 | 表单 | 每个模型族六个独立价：高峰/闲时 × 未命中输入/缓存命中输入/输出（单位元/每 1M tokens），留空 = 用内置价；「清空手动值」可整体回到内置价表 |

## 计费规则

高峰时段为北京时间 `09:00–12:00` 与 `14:00–18:00`，其余时间按闲时计价，闲时价是高峰价的一半；峰谷定价自 2026-08-17 00:00（北京）起生效，周末全天闲时价自 2026-08-23 00:00（北京）起生效。下表是 2026-09-03 官方价页的人民币价格（元 / 每 1M tokens），括号里是闲时 / 高峰：

| 模型族（前缀匹配） | 缓存命中输入 | 未命中输入 | 输出 |
|---|---|---|---|
| `deepseek-v4-flash*` | 0.05 / 0.10 | 1.5 / 3.0 | 4.5 / 9.0 |
| `deepseek-v4-pro*` | 0.15 / 0.30 | 4.5 / 9.0 | 13.5 / 27.0 |
| `deepseek-v4.1-flash*` | 0.05 / 0.10 | 1.5 / 3.0 | 4.5 / 9.0 |

（括号里是闲时 / 高峰；高峰 = 闲时 × 2，可在「价格配置」里对每一档单独覆盖。）

**模型 id 是自由字符串，不是官方模型名。** 匹配按三档进行：族前缀 → 显式别名（`deepseek-flash`、`deepseek-chat`、`deepseek-pro`、`deepseek-reasoner` 等，见 `lib/index.js` 的 `ALIASES`）→ provider 前缀兜底。本机实测同一个 provider 下三种写法共存：`deepseek-flash`（`settings.yaml` 的默认模型）、`deepseek-v4-flash`、`deepseek-v4.1-flash-expires-on-0910`，前两种已登记别名。`deepseek-v4.1-flash-*` 是 0910 试验版，官方没有单独价页，按 V4 Flash 价表计。推理 token 按输出价计费（`outputTokens` 全额）；2026-08-17 之前的事件没有峰谷价可比，计 0 并计入「未计价」提示。完全认不出、也不像 DeepSeek 的调用不计价并在页脚点名；像是 DeepSeek 但没价的**同样不计价，但会被点名要你补价**。

> 面板显示的是本地预估价，实际费用以 DeepSeek API 平台的账单为准（不含 Web 搜索、标题生成等平台侧调用）。

## 已知限制

「价格配置」表单里的模型族列表与默认价来自宿主（`meta.priceModels`），所以**官方价表新增一个族时需要改 `lib/index.js` 的 `FAMILIES` 并重启 DSH**——自动识别的是「同一族的新模型名」，不是「一个全新的族」。全新族的调用不会静默漏算：页脚会以「⚠ N 次调用认得模型但价表缺价」点名，你也可以在「价格配置」里直接为该族补价（手动覆盖对未知族同样生效）。

## 开发者

`lib/index.js` 是 Host 半区，注册 `deepseekBilling` 远程服务（`summary` / `status` / `setPrices` / `setRate`），计费引擎与动态预览版同源；`lib/client.js` 是 Client 半区，手写 `__ModuleLoader__.load` 格式，用纯 DOM 构建面板并注册成 DSH 官方右侧栏的一个标签页（经 `sidebarPanel` 服务；ui-beautify 未安装时退回自带的独立浮动卡）。价格与规则常量集中在 `lib/index.js` 顶部——`FAMILIES`（模型族 + 谷时价）、`PEAK_MULTIPLIER`（峰值系数）、`PRICE_AS_OF`（价表日期），改价时只需要动这三处；价表是**单一真源**，客户端不再自带副本。生效方式：Client 改动由 `dsh-client-hmr` 自动热重载（必要时 Ctrl+F5 兜底），Host 改动必须重启 DSH，因为 Node 的 ESM 模块缓存不会随文件变化失效。

## 更新日志

### v0.1.27
- **修复：手动配置价格后「本次窗口费用」不变。** 两个独立原因叠在一起：
  1. **覆盖存了但读不回来。** 表单写盘用的是**族 pattern**（`deepseek-v4-flash`），而真实调用的模型 id 是别名（`deepseek-flash`）。宿主 `offRow` 原来只用原始 id 去查覆盖表，所以表单里的值永远匹配不上 → 表现就是"配置了没效果"。现在覆盖查找按 **原始 id → 命中族 pattern → 别名指向的族** 依次尝试。
  2. **已折过的历史不重算。** `cost` 是在**折叠会话事件时**按当时的价表算好并累加进账户的，而 `scanSession` 用 `acc.cursor` 只折 cursor 之后的新事件 —— 所以改价后旧事件永远保留旧价。现在价格一变就丢弃所有活会话的账户，下一次 `summary` 全量重折（重折是幂等的：`foldEvent` 对同一个 `(turn,step)` 先冲抵旧样本再重算）。
- 说明：客户端保存成功的提示原本就写着"下次打开自动生效"，那其实是第 2 个原因的**症状**而不是设计意图 —— 现在改价后下一次轮询就会看到新数字（首次重折有一帧延迟）。
- 实现细节：丢弃账户必须**整体替换**而不是把 `cursor` 归零。账户里已经累加过旧价的总数，若保留累加器而清空按步样本，重折时 `foldEvent` 找不到 `prev` 就无法冲抵，会把同一批事件再加一遍（翻倍）。回归测试专门覆盖了这一点。
- 同时：只有值**真的变了**才失效缓存（客户端逐字段提交六个值，其中与当前相同的很常见），非法输入不会触发无效重折。

### v0.1.26
- **修复（重要）：本轮窗口费用恒为 ¥0.0000 的根因是模型名认不出。** 上一版我把价表改成「族前缀匹配」，但 pattern 写的是官方价页的模型名 `deepseek-v4-flash`。而 **DSH 的 model id 是 provider 配置里用户可自由填写的字符串**——本机 `settings.yaml` 里 `agent-default-model.model` 就是 **`deepseek-flash`**，`'deepseek-flash'.startsWith('deepseek-v4-flash')` 为假，于是 555 次调用全部归入「未识别模型不计价」。同一个 provider 里还有 `deepseek-v4-flash`、`deepseek-v4.1-flash-expires-on-0910` 两种写法共存 —— 这是**契约误读**（我假设 model id 等于官方模型名），不是单纯的命名差异。
  现在匹配分三档：**① 族前缀 → ② 显式别名表（`deepseek-flash` / `deepseek-chat` / `deepseek-pro` / `deepseek-reasoner` 等，登记了才会计价）→ ③ provider 前缀兜底**（认得「这是 DeepSeek 的模型」但没价时给出 `recognized` 而不是伪装成「非 DeepSeek 模型」，因此会在面板上被点名要你补价，仍不会静默算 0）。别名表随 `meta.priceAliases` 下发，客户端可据此诊断某个写法为什么算得出价。
- **变更：价格档位从「输入 / 输出」拆成三档——未命中输入 / 缓存命中输入 / 输出**，峰谷各一份，共 **六个独立输入框**。缓存命中价远低于未命中价（官方 V4 Flash：0.05 vs 1.5，差 30 倍），此前两档共用一个「输入」价会把缓存命中的调用严重高估。
- 兼容：v0.1.24 的四值结构（`valleyIn` 等）与更早的三值结构（`hit/miss/out` + `*Peak`）在读取时仍被正确折算，落盘的旧覆盖不会丢；客户端还会把按**具体模型名**保存过的旧覆盖按别名归并到对应的**族**键上（否则那些键再也不会被表单回填，看起来像"覆盖丢了"）。
- 修复：provider 兜底最初写了无横线的 `deepseek` 前缀，会把 `deepseekclone-x` 这类第三方模型误报成「DeepSeek 未定价」。已收紧为只认带横线的 `deepseek-`。

### v0.1.25
- **新增：用 DSH 自己的模型目录做交叉核对。** 宿主现在调用 `ctx.llm.listProviders()` / `ctx.llm.listModels(provider)`，把**当前供应商实际广告的模型**与我们认得的价格族相比，差集直接在面板页脚点名：「⚠ 当前供应商还广告了 N 个我不认识的模型（…）—— 未计价前不会算它的钱」。这解决的是"直到计费出错才发现价表没跟上"的滞后——现在换模型/加供应商后，只要打开面板就能看到。
- 新增：页脚区分三类缺价提示 —— `ⓐ` 认得族但价表缺价（已发生，按次数报）、`ⓑ` 供应商广告了但不认识族（未雨绸缪）、`ⓒ` 本会话真的用过且完全认不出（已按不计价处理）。三者互不重复。
- 说明：目录核对**只读缓存**。`listModels` 是异步的，而 `summary()` 是同步热路径，所以核对在插件启动时、以及每 10 分钟刷新一次；某个供应商不回应不会拖垮整轮。`llm` 服务缺席（headless / 未装 LLM 插件）时整块静默降级，面板不受影响。
- 修复：`meta` 的取值位置早于页脚提示块使用它的位置，会撞 `const` 的暂时性死区抛 `ReferenceError`（页脚整块渲染失败）。已把取值提到提示块之前。

### v0.1.24
- **修复（重要）：模型识别从「精确名」改为「按族匹配」。** 旧价表用 `OFFICIAL['deepseek-v4-flash']` 这种**完整模型名**查表，DSH 一发新模型名（带日期后缀的 `-expires-on-xxxx`、`-vision-*` 变体、带版本号的 `v4.1` 等），整类调用就会**静默变成「未识别模型不计价」**——实测出现过单会话 270 次调用全部不计价。现在按族前缀匹配（`deepseek-v4-flash*`、`deepseek-v4-pro*`、`deepseek-v4.1-flash*`），族的任意后缀变体都自动继承价格，并保留变体标签（如 `V4 Flash · vision-exp`）。
- **新增：计价结论三分类，不再静默漏算。** 每个模型名现在给出明确结论：`priced`（命中价表）/ `recognized`（认得族但这一档缺价）/ `unknown`（完全认不出）。第二类会在面板页脚**点名**提示"⚠ N 次调用认得模型但价表缺价（V4 Flash · xxx）—— 请在「价格配置」里补齐"，而不是混进"未识别"里悄悄算 0。
- **变更：手动价格覆盖改为四值独立。** 从 `hit/miss/out`（三档、峰值靠 ×2 推导）改为 **高峰输入 / 高峰输出 / 闲时输入 / 闲时输出** 四个独立输入框；留空表示用内置价。旧结构在读取时仍兼容（会自动折算），所以已有的 `localStorage` 覆盖不会丢。
- **变更：去掉「恢复官方」按钮，改为「清空手动值」。** 旧按钮做的事（清空手动覆盖回内置价表）与"保存空值"语义重叠，名字还容易被误读成"把官方价表拉回来"。
- **变更：价表单一真源移到宿主。** 客户端原来的 `DEFAULT_PRICES` / `MODEL_LABELS` 与宿主 `index.js` 各写一份、改价必然漂移，现已删除；客户端改为从 `summary` 的 `meta.priceModels` 拿族列表与默认价渲染表单。
- 注意：`setPrices` 现在收 `{ model, field, value }`（`field` ∈ `peakIn|peakOut|valleyIn|valleyOut`）；旧的 `{ model, bucket, valley, peak }` 仍被接受以便旧客户端继续工作。
